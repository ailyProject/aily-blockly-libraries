# ESP32 经典蓝牙 HID

本 Blockly 包提供46个积木，覆盖经典蓝牙键盘、鼠标、键鼠组合、媒体按键、通用手柄和实验性 Switch Pro 控制器。

## 库信息与支持环境

- 包：`@aily-project/lib-esp32-classic-bluetooth-hid`，版本 `0.0.3`，作者 `ailyProject`。
- 包装代码使用 MIT；预编译 Host 及第三方代码许可见随包 NOTICE 和原生库许可文件。
- 仅支持原始 ESP32（WROOM-32、WROVER），要求 Arduino-ESP32 **3.3.10 或更高版本**；不支持 ESP32-S3、C3 等其他芯片。
- 请选择 Arduino-ESP32 3.3.10 或更高版本的 SDK；本包不会自动下载、替换或升级 SDK。

`src/ESP32ClassicBluetoothHID/` 与 `src/ESP32BluetoothSwitchProController/` 中已内置两个独立 Arduino 库的生产源码、库元数据、预编译 Host 和许可。它们没有合并成一个原生库，用户也无需另行安装 Arduino 库。Blockly 辅助层 `AilyClassicHIDProfiles.h` 在原生接口之上提供媒体、通用手柄和参数校验。

## 初始化和运行方式

1. 在 setup 中放一种对应模式的初始化块，再使用该模式的积木。初始化调用在积木实际所在位置执行，不会被自动提前。
2. 六种模式互斥，只有键鼠组合模式可以同时使用键盘和鼠标积木。不同模式初始化或不兼容的功能组合会拒绝生成代码；即使中间放了停止块，也不能在一个工作区切换成其他设备类型。
3. 同一模式可放多个初始化块，用于停止后重新启动。没有初始化块时，生成器可以按功能推断对象类型，但不会自动启动蓝牙。
4. loop 开始自动加入一次 `update()`；长循环内可用“更新经典蓝牙设备”积木。避免长时间阻塞，特别是 Switch 模式和等待媒体按键自动释放时。
5. 不能与 BLE、NimBLE 或 BluetoothSerial 并发使用蓝牙控制器。“清除配对”会同步等待完成。

“最近一次初始化成功”是最近的 begin 结果；“最近一次操作已接受”只表示本地接受，不保证远端实际收到。错误可从“最近错误”查询，异步错误也可能在此前本地接受成功后出现。

## 各模式约定

| 模式 | 功能与范围 |
|---|---|
| 键盘 | US ASCII、US主机布局；6个普通键和8个修饰键；CRLF只产生一次Enter。ASCII按键要求单字节，主机LED状态不是GPIO控制 |
| 鼠标 | 五按钮；X/Y/滚轮整数 -127～127，X向右、Y向下为正；Boot只支持三键和X/Y |
| 键鼠组合 | 同一连接中同时使用上述键盘和鼠标通道 |
| 媒体按键 | Report ID 3、16位Consumer Usage；音量增减、静音、播放暂停、上下曲和停止；约20ms后非阻塞释放，忙碌时拒绝积压按下，失败只回到中立 |
| 通用手柄 | Report ID 4；按钮1～16、16位按钮掩码、四轴整数-127～127且Y向下为正；方向帽0上、顺时针到7左上，8中立；复位释放按键并居中 |
| Switch Pro | 摇杆整数-32768～32767，0居中且Y向上为正；方向键、按键、报告模式及协议诊断；仍属实验适配 |

媒体和通用手柄仅支持Report模式。鼠标失败恢复使用当前按钮状态和零位移，不重复失败的移动；连接恢复不应重放离线积压按键。

Switch电量仅设置报告中的百分比和充电标记，不检测实体电池。IMU/振动状态表示主机请求，rumble只是原始协议字节，不能据此声称存在传感器或驱动马达。玩家指示灯返回位图，主动连接要求合法的主机MAC地址。

本包尚未进行ESP32上板、PC配对、媒体映射、GPIO接线或Switch实机互通验证。完整46块签名、参数枚举和完整ABS程序见[AI编程指南](readme_ai.md)。原有6个状态示例保持只读；另有6个动作示例演示连接判断、用户触发和释放/回中。每个示例应作为独立工作区使用。

## 工具箱与按键语义

工具箱只使用两级分类：第一级为 ESP32 经典蓝牙 HID 库，第二级依次为初始化、连接状态、连接管理、键盘、鼠标、媒体按键、通用手柄和 Switch Pro 控制器。各设备的积木直接列在对应分类中，不设第三级；常用输入在前，原始编码、掩码和协议功能在后。全部 46 个积木及各级分类均使用软件内置图标，按设备或功能区分。

- “按住”对应 `PRESS`，会持续到“松开”或“释放全部”；把它放进循环不会自动变成单击。
- 鼠标“单击”会自动松开；文本与快捷键会完成自己的释放。快捷键会释放调用前已保持的所有键。
- 快捷键除8个单修饰键外，还可直接选择 Ctrl+Shift、Ctrl+Alt、Ctrl+Alt+Shift 和 Win/Cmd+Shift。
- Raw Usage 是 HID 使用码，不是 ASCII。只接受0x04～0xA4、0xB0～0xDD及修饰键0xE0～0xE7；普通场景优先用命名按键。
- “如果”必须有完整条件。连接状态变为真并不代表只执行一次，输入动作还应有按钮或命令触发条件。

## 动作示例

串口示例使用115200波特率，建议选择“不发送行尾”。每次只发一个小写命令字节；未连接时收到的命令会被丢弃，连接后不会重放。按键短按示例在20ms等待前后显式更新；媒体示例由自动更新完成约20ms后的释放。

| 文件 | 用户操作与行为 |
|---|---|
| `examples/keyboard_input.abs` | 发a：A按住约20ms后松开 |
| `examples/mouse_input.abs` | 发m：鼠标向右移动10并左键单击 |
| `examples/keyboard_mouse_input.abs` | 发c：同一键鼠设备发送Ctrl+C并移动鼠标 |
| `examples/media_keys_input.abs` | 发p：空闲时切换播放/暂停，忙碌时丢弃该次命令 |
| `examples/gamepad_input.abs` | 发b：按钮1短按后释放全部并将摇杆/方向帽回中 |
| `examples/switch_pro_input.abs` | GPIO25和GND之间接按钮：A跟随按住/松开状态；此例未实现机械按键消抖 |

这些示例展示输入时序，不代表已经完成无线配对或实体设备互通测试。

已有编译基线（2026-10-29）：使用 aily Builder 1.2.17 和官方 Arduino-ESP32 3.3.12，两个原生库的全部 12 个示例、Print 兼容性检查及 Blockly 六种模式的实际生成代码全部完成编译和链接；官方 3.3.10 的 Switch Pro Basic 与 HID Keyboard 两个示例也完成最低版本编译和链接检查。捆绑 Host 归档保持不变。未进行 ESP32 上板、PC 配对或 Switch 实机互通验证。
